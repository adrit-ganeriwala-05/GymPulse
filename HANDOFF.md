## 1. State of the project

**What it is.** Single-user, offline-first Flutter gym tracker: start a session, add exercises, log sets (reps × weight), rest timer between sets, finish → SQLite; daily streak with two rest-day tokens per ISO week; History (edit/delete via long-press; tap an exercise for its progress and PR), month Calendar, kg/lbs display toggle. No backend, no network, no auth. Android + iOS + macOS.

**Current state.** `main` at `f05ab33` is what GitHub has. Round 6 (A2-08 enforcement + Feature D + schema v4) is an **uncommitted working tree** on top of it: the owner stages and commits it under their own name. The four working documents (`HANDOFF.md`, `project_context.md`, `WALKTHROUGH.md`, `FEATURE_PROPOSALS.md`) were removed from the repo in round 5 at the owner's request and restored as untracked files for round 6; whether they go back into the repo is the owner's call.

**Verified, and how** (execute these; do not trust the numbers):
- `flutter analyze` → clean.
- `flutter test` → **141** tests: datasources 61 (streak 29 · workout on real SQLite via `sqflite_common_ffi` 16 · migration hops 5 · progress aggregate 11) · repositories 3 · domain 16 (stats 8 · progress rules 8) · blocs 27 (Workout 15 · WorkoutTimer 8 · RestTimer 4) · screens 25 (Active 10 · Home 6 · History 2 · Onboarding 2 · Calendar 1 · Exercise progress 4) · router 4 · widgets 2 · units/settings 3.
- `flutter test integration_test/app_flow_test.dart -d <device>` on the Android emulator (Pixel 9 Pro XL, API 37) and the iOS simulator (iPhone 17 Pro, iOS 26.3): seeds a **v1** database, walks onboarding → workout → validation → rest sheet → finish → calendar → history delete → exercise progress (PR on the real plugin) → edit. Both green at the end of round 6 — see §7 for the exact lines.
- Migration ladder (**v4**): every hop — v1→v2, v2→v3, v3→v4 — on a hand-built file at that version, plus v1→v4 through the app's opener asserted byte-equal in shape to a fresh v4 (unit, ffi); v1→v4 on the real plugin on both platforms (integration).
- Process death: the Android harness reinstalls the APK each run (see §6), so this was verified by hand once in round 3: `flutter build apk --debug`, `adb install -r`, start a session, `adb shell am force-stop com.example.gympulse`, relaunch → banner, resume paused at the checkpointed elapsed. **Redo this if you touch draft persistence.** It is not automated.

**Architecture** in one paragraph: Clean Architecture, `presentation → domain ← data`, `get_it` composition root in `injection_container.dart` (use cases singletons, blocs factories), `go_router` 13 with `/active` nested under `/`, `flutter_bloc` 8 with `bloc_concurrency` `sequential()` on read-modify-write handlers, `sqflite` schema **v4** with an `onUpgrade` ladder, `shared_preferences` for streak/settings/onboarding. One read model (`domain/read_models/exercise_progress.dart`) with its own `ProgressRepository` — the first query SQLite computes instead of the app hydrating entities. Full map: `project_context.md`. Rationale per decision: `WALKTHROUGH.md`.

## 2. How to work here

These are the conventions four rounds settled into; the rounds that skipped one paid for it.

- **Branch before a round.** `git checkout -b roundN`. The current tree is device-verified and must stay recoverable.
- **Audit before fixing.** Write the finding (severity, location, symptom, root cause, repro, fix, blast radius — the `BUG_REPORT.md` / `AUDIT_2.md` format) before touching code. Fix in severity order, one commit per cluster.
- **Reproduce before you call it a bug.** A failing test or an observed device behaviour. Every finding in `AUDIT_2.md` has one; the ones that could not be reproduced are labelled suspicions. Source-reading alone produced false positives in round 1 and missed the worst bugs in rounds 3–4.
- **Verify by execution, never by assertion.** "Tests pass" means you ran them in this session and pasted the count. A test that has never been seen to fail is not evidence — round 4 found three that could not fail, and round 5 had to prove the DST tests could (§6).
- **Edit surgically.** No rewrites. Append to audit files; correct stale lines in place.
- **Docs are claims.** `FIXES.md` said "nothing remains broken that I know of" one round before a High was found on the retry path it described. Read every "verified" as "verified by someone else, at some commit, under some assumptions".
- **Device runs are the expensive step.** Batch them: one per platform at the end, plus whatever a specific repro needs. Widget tests with real blocs and the real datasource catch most things first.
- **Version control is the owner's.** Do not commit, push, stage, amend, tag or create branches, and do not add any attribution trailer — that convention is retired. Leave work as uncommitted changes and end with a change list and a suggested commit grouping. Analyzer must be clean before you hand over. New dependencies need a justification (approved so far: `bloc_concurrency`, `sqflite_common_ffi`, `integration_test`, `fake_async`).

## 3. Load-bearing invariants, thinly enforced

A newcomer will break these without knowing they exist. For each: what, what breaks, where enforced.

| Invariant | What breaks if violated | Enforced where |
|---|---|---|
| **`status = 'done'` on every read.** Drafts are ordinary `workouts` rows with `status = 'draft'`; every read filters them. | A draft appears in History/Calendar/"This week"/"Longest run"; a draft's heavy set becomes a PR. | `getWorkouts` and both progress queries repeat the filter. Tests: "an open draft is invisible to every aggregate", "an open draft with a heavier set creates no PR". v4 adds `CHECK (status IN ('done','draft'))` — that stops a *bogus* status, it does **not** filter for you: any new query must repeat the `WHERE`. |
| **One draft at a time.** v4 partial unique index `one_draft`; `WorkoutBloc._onStarted` never falls through to a fresh session on a failed read (`WorkoutUnavailableState` + Retry); Home's Discard deletes all drafts; `getDraft` asserts ≤ 1 in debug. | A second draft row hidden behind `LIMIT 1` forever, or (with the index) checkpoint writes failing mid-session. | Index + bloc + assert. Tests: "a second draft cannot be inserted…", "draft read failure → Unavailable…", "deleteDrafts removes every draft row". |
| **`name_key` is written only by `upsertWorkout`, always via `normalizeExerciseName`.** | Progress splits one exercise into two series; the bloc's in-session dedupe disagrees with the stored key. | The datasource insert and the v4 backfill both call the one function; SQL never computes it (`lower()` is ASCII-only). Tests: "exercises are stored with a normalised name_key", v3→v4 backfill of `' Bench '`/`'Über Row'`. |
| **Elapsed time is state, never wall-clock.** `WorkoutInProgressState.elapsedSeconds` + `timerPaused`, checkpointed every 10 s and on pause/stop/reset/resume-edge; resume seeds the timer from it. | A draft resumed after three days reads as a 72-hour workout; a kill loses more than 10 s; a paused session resumes running. | `_ActiveBody` checkpoint listener + `RecordDraftElapsed` (single-column `UPDATE`). Tests: bloc "elapsed checkpoints…", "paused at death…", screen "resuming a paused draft". Nothing stops a future widget from computing `now − startedAt`. |
| **Weight is kilograms everywhere below presentation.** Conversion only in `presentation/units.dart` at parse (`ExerciseLogCard._submitSet`) and render (`formatWeight`). | Toggling kg/lbs relabels history instead of converting it (BUG-01); volumes sum mixed units. | Comment on `ExerciseSet.weight`; tests "display <-> kg round-trips", "editing twice leaves stored weights bit-identical". No type distinguishes kg from display units — a `double` is a `double`. |
| **A draft is a workout row; finishing flips it in place.** Same `id`; the upsert is `DELETE` by id then plain `INSERT` (not `INSERT OR REPLACE` — that would satisfy a `one_draft` conflict by silently deleting the *other* draft). Children are recreated by cascade (FKs ON via `onConfigure`, the only hook where the pragma takes effect). | Two rows per workout; orphaned children if FKs are off; a lost draft on an index conflict. | `upsertWorkout`; tests "finishing a draft flips it in place", "re-saving replaces children", "foreign keys are enforced", "a second draft cannot be inserted… the first is intact". |
| **Progress rules live in domain; SQL only reduces per workout.** The civil-day fold (`civilDate`) and the PR ordering (weight, then reps; earliest day keeps a tie) are in `ExerciseProgress.fromWorkoutTopSets`. | A second definition of "day" (e.g. `substr(date,1,10)` or `date()` in SQL) or of "PR" drifting from the domain's; BUG-03 back via new date math. | Domain tests name each rule; the DST fold test sets the zone and was seen to fail against elapsed-hours arithmetic. Do not move bucketing into SQL. |
| **`last_streak_day` never moves backwards.** Continuity marker; rest days advance it, backdated workouts do not retract it. | A backdated credit (finished draft) un-bridges a rest day; streak reads 0 while the calendar shows a run. | `StreakLocalDatasourceImpl.updateStreak` (`max(existing, day)`); test "backdated workout inside a rest-bridged chain". |
| **Streak credits the workout's start day.** `updateStreak(on: workout.date)`; a day at or before the last credited workout is history. | Calendar and streak disagree; a real workout later the same day does not count (A2-03). | `WorkoutBloc._onFinished`; datasource group "updateStreak(on:)". If you change the row's date policy, change this with it. |
| **One rule for "can I rest today".** `canMarkRestDay()` is the datasource's guard *and* the Home button's visibility. | Dead button (A2-02) — every user, every rest day. | `GetStreak` → `StreakLoadedState.canRestToday`. Do not re-derive it in a widget. |
| **Stop/Pause are sent only to a clock that can honour them.** The timer reads from Running *or* Paused; Save & Finish reads the duration and does not stop the clock. | Retry after a failed save stores `duration 0` (A2-01, High). | `WorkoutTimerBloc._seconds`; tests "stop while paused keeps the reading", "save fails → retry still saves the original duration". |
| **Write ordering of the draft.** On-disk draft = latest emitted state because every handler emits *before* its first `await` and sqflite is FIFO on one connection. `sequential()` only prevents same-type interleaving. | A slow write persisting an older snapshot after a newer one. | Convention in `WorkoutBloc` handlers. No test pins "emit before await"; if you add an `await` above an `emit`, you have broken it. |
| **`PopScope` on `/active` only works because `/active` is a child of `/`.** | Android system back exits the app mid-workout (round 3). | `router.dart` nesting; `router_test` "system back from /active reaches PopScope". |

## 4. Open work, ready to pick up

### Untested surfaces (and why each was left)
- **`CalendarScreen` rendering** beyond one tap-to-detail test: `table_calendar` internals; the only app logic (UTC day → local key) is pinned.
- **`StreakBloc`** handlers: three pass-throughs over a 29-case datasource; `SharedPreferences` reads cannot throw.
- **A2-01 / A2-02 / A2-08 on a device with an injected failure.** Verified by widget tests with the real datasource / real blocs (the Unavailable + Retry path included). Injecting a disk failure on a device needs a debug hook the app does not have; not worth adding for a check the widget tests already make.
- **DST on a device.** Unit-level only (§6); the simulators run in the host zone.
- **The exercise-progress screen's bars** are checked for text and badge placement, not pixel proportions. The aggregate itself is tested on real SQLite (11 cases) and once on each device.

### Deferred by choice
- **Best-vs-current streak reconciliation (BUG-09).** "Longest run" counts workout days; the streak card also counts marked rest days as bridges. They cannot agree until rest days are *rows* the stats functions can see. That is a schema step (`rest_days` table or a `kind` column) plus a backfill from prefs — a feature, not a fix. Tile was renamed so the UI does not lie.
- **N+1 read past ~2,000 workouts.** `_hydrate` issues one query per workout and one per exercise. At a solo user's volume that is ~1,200 cheap local reads, sub-100 ms. A JOIN-shaped read model is the fix when it becomes visible; comment in `_hydrate`.
- **Localization, accessibility, dark mode.** None started. Strings are inline, colours are hex literals in one `ThemeData`, no semantics labels beyond tooltips on the remove buttons. Each is a sweep of every screen; none was in any brief and none blocks the others. If you start one, dark mode first — the theme is one literal and the hex literals in widgets are the audit target.
- **HistoryBloc / reactive reads.** See §5 — it is a prerequisite, not a deferral.
- **The live "new PR" badge on save.** Deferred by decision, not by accident: it is the only part of Feature D that needs a reactive read path. First in line after `HistoryBloc`.

### The largest real-world gap: no backup, export, or sync
The entire history is one SQLite file (`gympulse.db`) plus a handful of prefs on one device. Uninstall, lose the phone, or hit `onDatabaseDowngradeDelete` on an app downgrade, and it is gone. This is a **design decision** (single-user, offline-first, no accounts), not a bug — but it is the first thing a real user loses sleep over. The cheapest step is an export (JSON or CSV via the share sheet) which needs a codec (the old JSON one was deleted as dead code; write a new one in `data/`) and a platform share plugin (new dependency, needs justification). Sync is a different product.

## 5. Proposed features, with enough design to start

**First, the prerequisite.** The app has **no reactive read path**. Home, History and Calendar each call `sl<GetWorkouts>()` in `initState` and render a `FutureBuilder`; they refresh only on remount or on an explicit `_reload()` (Home also on `RouteObserver.didPopNext`). Nothing updates while a screen is alive. Any feature that changes data the visible screen shows — templates applied mid-session, a PR computed on save, rest-day rows — pays for this first. The named refactor is a **`HistoryBloc`** (or a repository `Stream<List<Workout>>` fed by a `StreamController` the datasource pokes after every write) that Home, History and Calendar all subscribe to. Touches presentation only; no schema; risk is low but it is the one change that reaches every screen, so do it alone in its own round with the widget tests as the net.

| Feature | What it does | Layers | Schema | Forces the app to grow | Main risk |
|---|---|---|---|---|---|
| **C — Routine templates** (from `FEATURE_PROPOSALS.md`) | Save "Push day" as a template; start a session pre-populated. | data (two tables), domain (`Template` entity, `SaveTemplate`/`GetTemplates`/`StartFromTemplate`), presentation (template list, "Save as template" on Finish, picker on Begin). | **v5**: `templates`, `template_exercises`. Additive `CREATE TABLE`s in the next ladder step. | A second aggregate root; a template picker screen; the first seeded-state path into `WorkoutBloc` (`WorkoutStarted(from: template)` — must not fight draft resume: define precedence, draft wins). | Interaction with drafts: starting from a template while a draft exists. Decide before code. |
| **D — Per-exercise progress and PRs** — **shipped in round 6 without the live badge** | Tap an exercise in History → top set per day, PR badge on the record. | Done: `ProgressRepository` + read model in domain, SQL aggregate in data, `/exercise` screen. | Done: v4 `name_key` + index. | Done: the first query-shaped read model. | Remaining: the **live "new PR" badge on save** needs the reactive read path — build it right after `HistoryBloc`; it is one listener on the finish path plus a flag on the set row. |
| **E — Rest days as rows** (suggested by BUG-09 / round 3) | Rest days become data: calendar marks them, "Longest run" and the streak card agree, streak can be rebuilt from history. | data (`rest_days` table, backfill from prefs on migration), domain (`streak_rules` gains a pure `computeStreak(workoutDays, restDays, today)`), presentation (calendar marker, legend restored). | **v5**: `rest_days(date TEXT PRIMARY KEY)`; backfill from `last_rest_day_date` (only one day is recoverable — accept it). | A derived streak instead of a counter in prefs: the streak becomes a *query*, which also fixes the two-sources-of-truth class of bug (A2-02/03) at the root. | Behaviour change for existing users (the counter may differ from the recomputed value on upgrade). Needs a migration note and a decision on which wins. |
| **F — Export** (from §4) | Share the history as JSON/CSV. | data (codec), presentation (menu item), one plugin. | None. | A serialisation format that is now a compatibility surface; a share dependency. | Low. |

**Recommended order and why.** (1) `HistoryBloc` / reactive reads — everything below needs it and it is cheapest while the screens are simple; the exercise-progress screen is now a fourth `FutureBuilder` copy of the read path and should be folded in. (2) **The live PR badge** — the deferred half of D; small once (1) exists. (3) **E — rest days as rows** — converts the streak from a counter into a derivation, removing the "two definitions" class that produced BUG-07/09/10 and A2-02/03; a v5 step. (4) **C — templates** — additive, low risk, least urgent; bundle its tables into the same v5 step as E if both are going in. (5) **F — export** whenever the owner wants the safety net; independent of the rest. Do **not** start C before (1): it would add another `FutureBuilder` copy.

## 6. Traps (each cost real time)

- **`flutter test integration_test/…` on Android reinstalls the APK on every run and wipes app data.** Observed: run 2 of the same file printed `Installing …app-debug.apk` and the prefs marker was gone. Cross-launch persistence cannot be proven through the harness. Use a real debug build: `flutter build apk --debug` → `adb install -r` → drive the app → `adb shell am force-stop com.example.gympulse` → relaunch → `adb exec-out screencap -p > shot.png`. `integration_test/draft_death_test.dart` documents this and is *not* proof.
- **go_router 13 `popRoute` bypasses `PopScope` on a root route.** `delegate.dart:59` nulls the navigator when it cannot pop and never calls `maybePop`, so Flutter falls through to `SystemNavigator.pop()` — Android back exits the app. That is why `/active` is a **child of `/`** (`GoRoute(path: 'active')` nested), so `go('/active')` builds `['/', '/active']` and the gesture reaches the Navigator. Consequence: Home persists beneath and refreshes via `RouteObserver.didPopNext`. Move `/active` to the root and the round-3 bug returns; `router_test` will catch it.
- **sqflite single-instances and serialises `openDatabase` per path** (`sqflite_common` `factory_mixin.dart:74,94`). A "concurrent open opens once" test cannot fail. The observable branch of `WorkoutDatabase` is the failed-open reset (`catchError` → `_databaseFuture = null`); test it with `databaseFactory.setDatabasesPath('/unwritable')`. Also: you cannot substitute a custom `DatabaseFactory` subclass — the setter rejects unknown types.
- **DST tests are meaningless unless the zone is set inside the test.** Dart's `DateTime` asks libc; the host's `TZ` is inherited. `test/helpers/tz.dart` sets `TZ` via `setenv` + `tzset` (raw `dart:ffi`, POSIX hosts) and each DST test asserts the 23 h gap is really present. Proven in round 5: with the old `inDays` arithmetic patched in and `TZ=UTC` on the host, all three fail; with the fix, all pass. If you add a DST case, use the helper and the gap assertion, and *watch it fail once*.
- **`google_fonts` weights fail at runtime only.** Runtime fetching is disabled (BUG-21); every `FontWeight` used anywhere must map to a bundled `assets/fonts/Family-Variant.ttf` (`DMSans-Bold.ttf`, `PlayfairDisplay-SemiBold.ttf`, …). A missing face throws on first paint on a device and is invisible to `flutter test` (Ahem font). Grep call sites before adding a weight.
- **The Ahem test font is ~2× wider than the bundled faces.** Home's title rows overflow at a 400 px test surface but not on a 402 pt iPhone. Widget tests that need a phone-width surface use 600 px (`router_test`) or accept that some rows are not the thing under test. A `RenderFlex overflowed` in a test at 400 px is not evidence of a device bug without a device screenshot.
- **`onConfigure` is the only place `PRAGMA foreign_keys` works.** Inside `onCreate`/`onUpgrade` (a transaction) it is a silent no-op. Cascades — which the upsert *relies on* — depend on it.
- **`DROP TABLE` on a parent with foreign keys ON cascades into the children.** It performs an implicit `DELETE FROM` first, and FK *actions* fire on it. The textbook rebuild (create new, copy, drop old, rename) therefore wipes `exercises` and `sets` when you drop `workouts`, and you cannot turn FKs off inside the upgrade transaction. The v4 step renames the old tables away, creates the new ones under the final names with `_createDB`'s DDL, copies, and drops the old set children-first. Reuse that shape for v5.
- **The ladder runs step N iff `old < N <= new`.** Same behaviour for the app; it is what lets `migration_test.dart` drive one hop at a time. If you add a step, add its hop test on a hand-built file *at the previous version* — the full-chain test alone cannot see a step that re-applies an `ALTER` already present.
- **`INSERT OR REPLACE` satisfies *any* unique conflict by deleting the other row** — including the `one_draft` partial index, which would silently delete the other draft. The upsert is `DELETE` by id + plain `INSERT` for that reason; keep it that way.
- **Test files run in parallel isolates and share `getDatabasesPath()`.** Two ffi test files using `gympulse.db` interfere intermittently. Every datasource test file calls `databaseFactory.setDatabasesPath(<its own temp dir>)` in `setUpAll`; a new one must too.
- **SQLite's `lower()` is ASCII-only.** Never compute `name_key` in SQL; `normalizeExerciseName` (Dart, Unicode) is the only writer, including the migration backfill.
- **Bloc `sequential()` is per event type.** See §3. Do not "fix" ordering by changing the transformer.
- **`_reload() => setState(() => x = …)`** returns the assignment's Future from the callback and the framework asserts. Block bodies in all three screens; keep it that way.
- **Rest-timer bottom sheet.** Two documented `!_debugDoingThisLayout` workarounds (open on the next frame after dropping the keyboard; pop on the next frame after finish). Re-verify on a device if you change how it opens or closes. Its Start button lays out below the fold under the test font — the auto-close test drives the bloc directly.
- **Spend estimates from token volume run ~40 % high.** Report them as estimates and ask the owner to read the console.
